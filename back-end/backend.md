# Backend

FastAPI service for auth, chat persistence and the RAG pipeline. Entrypoint: `main.py` (`uvicorn` on `127.0.0.1:8000`). Dependencies: `requirements.txt`.

## Layout

```
back-end/
├── core_endpoints/   # auth.py, chat.py, admin.py, rag.py
├── services/         # database.py (SQLite), rag_service.py (Qdrant + Ollama)
├── config.py         # env vars, CORS, password/JWT setup
├── models.py         # Pydantic schemas
├── main.py           # app + routes + static file serving
└── .env              # secrets (git-ignored)
```

## Database (SQLite: `data/users.db`)

- **users**: `id`, `full_name`, `username` (unique), `password` (bcrypt), `is_admin`
- **login_sessions**: `session_number` (PK), `token` (unique), `status` (`active`/`revoked`), `user_id` (FK), `created_at`
- **chat_sessions**: `id`, `user_id` (FK), `title` (default `New chat`), `created_at`, `updated_at`
- **chat_messages**: `id`, `session_id` (FK), `role` (`user`/`assistant`), `content`, `created_at`
- **personas**: `id`, `name`, `prompt`, `created_at` (seeded with defaults on first run)

Tables are created on import in `services/database.py`.

## Auth

- Login issues a JWT signed with `SECRET_KEY` containing `sub`, `user_id`, `role`, `jti`, `exp` (24h) and stores the token in `login_sessions`.
- Protected routes use `check_token` (`auth.py`): decode JWT, then confirm the token is `active` in the DB (revocation after logout).
- Admin routes use the same Bearer token via `require_admin` (`auth.py`), which enforces the `admin` role.

## RAG pipeline (`services/rag_service.py`)

- **Ingest:** extract text (`.txt`/`.md` decode, `.pdf` via `pypdf`, `.docx` via `python-docx`) → semantic chunk (`SemanticSplitterNodeParser`) → embed via Ollama → store in Qdrant.
- **Chat:** if a Qdrant collection exists, retrieve top-k chunks and answer with `CondensePlusContextChatEngine` (French prompts); otherwise fall back to a plain Ollama chat.
- **Bulk initial load:** POST `/upload` per file (any authenticated user) or POST `/ingest` with raw text (admin). See the README "Ingesting data" section.
- Session titles are generated by the LLM on the first exchange.
